# 后台启用清单

一句话现状：**代码这边齐了，线上有三个变量还没填，所以「保存」一次都没成功过。**

填完就是下面这四步。**这一步只能在 Cloudflare 控制台做，本地做不了** —— 这台电脑上没有
Cloudflare 的登录凭据，代码推上去之后 Cloudflare 会自己重新构建，不需要在本地做别的。

---

## 一、照着做：四步

### 第 1 步 · 想一个后台口令，算出它的哈希

1. 双击打开 **`_gen/口令转哈希.html`**（用浏览器打开就行，纯本地页面，不联网）
2. 在第一个框里敲你想用的后台口令。随便定，比如 `MyBlog-2026`
3. 下面会自动出现一串 64 位的字符，点右边的「复制」
4. **口令和这串都记一下**：口令是你以后登录要输的，这串是填给服务器的
5. 同一页第 2 块还有一串随机的 `AUTH_SECRET`，也点「复制」备着

不想用页面，命令行也一样：

```bash
node _gen/hash-password.mjs "你设的口令"
```

> 为什么要多这一道：服务器不存你的口令，只存它的 SHA-256。登录时算一遍、比一比。
> 这样哪天服务器被人看到，也拿不到你的口令。值是**算出来的**，不是你想一个填一个。

### 第 2 步 · 去 GitHub 申请一个令牌

1. 浏览器打开 <https://github.com/settings/personal-access-tokens/new>（要先登录）
2. **Token name** 随便填，比如 `blog-admin`
3. **Expiration** 选个够用的，比如 1 年（到期要重做第 2、3 步）
4. **Repository access** 选 `Only select repositories`，再选中你的博客仓库 **WWPPL**
5. **Permissions** → **Repository permissions** → 找到 **Contents**，右边改成 **Read and write**
6. **Permissions** → 往下拉到 **Account permissions**（旧文档里叫 *User permissions*）→
   找到 **Gists**，右边改成 **Read and write**
7. 拉到页面最下面，点 **Generate token**
8. 页面顶部会冒出一串 `github_pat_…`，**只显示这一次**，马上复制下来，先粘到记事本里

> ⚠️ **第 6 步最容易漏，而且漏了很难查。** 只做第 5 步会「能用一半」：
> 写文章、传图片、换头像都正常，**但说说和笔记存不进去**。
> 原因是 GitHub 对没权限的 Gist 回的是「找不到」而不是「没权限」，报错会绕一圈才看明白。

不想折腾细粒度令牌也行，换经典令牌：<https://github.com/settings/tokens/new>，勾 `repo` 与 `gist` 两项。

### 第 3 步 · 把三个值填进 Cloudflare

1. 打开 <https://dash.cloudflare.com> 并登录
2. 左侧找 **Compute / Workers & Pages**，在列表里点 **firefly**
3. 页面上方选 **Settings** → 找到 **Variables and Secrets**
4. 点 **Add**，类型选 **Secret**，然后一个一个加：

   | Variable name | Value 从哪来 |
   |---|---|
   | `ADMIN_PASSWORD_HASH` | 第 1 步复制的那串 64 位字符 |
   | `AUTH_SECRET` | 第 1 步那串随机密钥（配不配都能跑，建议配） |
   | `GITHUB_TOKEN` | 第 2 步复制的那串 `github_pat_…` |

5. 三个都加完，点 **Deploy** —— **不点这一步等于没填**
6. 等它重新部署完（页面上会显示进度，成功就是好了）

> 名字必须一字不差、全大写。类型选 **Secret** 之后，值在页面上就再也看不见了（正常，能改不能看）。

### 第 4 步 · 确认真的通了

最快的一条：打开 <https://wwppl.dpdns.org/admin/>，输入第 1 步那个口令。

- **登不进去** → 登录框下面会写出原因，对照第四节那张表
- **进去了** → 去「说说」页发一条。这条走 Gist、**刷新就能看到，不用等重建**，
  正好顺手验证第 2 步的第 6 步有没有做对
- 想看机器给的结论：跑一次 `node verify/2026-09-23/线上巡检.mjs`，
  最后一节「后台就绪度」里两个变量会从「未配置」变成「已配置」

**存进去了没有？** 后台页面自己说「已保存」不算证据 —— 想知道是不是真写进了 GitHub，
跑一次 `node verify/2026-09-24/后台写入落点核验.mjs`。它绕开令牌和登录，
直接从 GitHub 公开地址读结果（说说看 Gist 条数、笔记看六个笔记本、文章看仓库提交），
并跟上次的记录比一比，明确告诉你「变了什么」。第一次跑存一份基线，之后每次都能对比。

## 二、填完之后，一条保存会经过什么

| 后台页面的动作 | 实际写到哪里 | 怎么生效 |
|---|---|---|
| 写文章 / 改文章 / 删文章 | 仓库 `src/content/posts/**` | 触发 Cloudflare 重建，1~3 分钟上线 |
| 上传文内图片、封面 | 仓库 `public/images/posts/<文章>/` | 同上 |
| 换头像 | 仓库 `public/assets/avatar.png` | 同上 |
| 写说说 | 一个 GitHub Gist 里的 `moments.json` | 页面刷新即见，**不用等重建** |
| 写笔记 | 一个 GitHub Gist 里的 `notebooks-entries.json` | 同上 |

两条路都**必须经过服务端的 `/api/github` 代理**：令牌只放在服务端，浏览器拿不到它。
浏览器里不管做什么都要先过登录这一关 —— 这也是为什么第 1 步那个变量不能省。

## 三、三个变量各自的注意点

位置：**控制台 → Workers & Pages → firefly → Settings → Variables and Secrets**

### 1. `ADMIN_PASSWORD_HASH` —— 后台登录口令的哈希

**它不是某个固定值，而是「你自己定的那个口令」算出来的 SHA-256**，一共 64 位、全是十六进制字符。
口令他定，值由它推出来。生成一次、把口令记牢就行。

| 填什么 | 结果 |
|---|---|
| 口令的 SHA-256（小写 64 位十六进制，如 `b5c3…`） | ✅ 正确 |
| 你的口令原文，如 `MyBlog-2026` | ❌ 登不进去，登录页会直接提示「填得不对」 |
| 少几位、多一个符号 | ❌ 同样提示「填得不对」 |

生成方式（任选一种）：

```bash
# 本机脚本，会顺手自查一遍
node _gen/hash-password.mjs "你设的口令"

# 或者 node 一行
node -e "console.log(require('crypto').createHash('sha256').update('你设的口令','utf8').digest('hex'))"
```

```powershell
# 只有 PowerShell
[BitConverter]::ToString([Security.Cryptography.SHA256]::Create().ComputeHash([Text.Encoding]::UTF8.GetBytes("你设的口令"))).Replace('-','').ToLower()
```

填的时候注意四点（已写进 `verify/2026-09-24/保存链路核验.mjs`，共 9 项断言）：

- **口令不做裁剪**：`abc ` 与 `abc` 是两个不同的口令。生成时带了空格，登录时也要带空格。
- **大小写十六进制都认**：服务端会先归一成小写再比。
- **粘贴蹭上的空格／换行会被忽略**：值两侧的空白不影响。
- **换口令 = 换密钥**。它是会话 Cookie 的签名密钥来源，改它等于让所有登录状态失效（重新登录即可）。
  想让换口令不影响登录状态，就把 `AUTH_SECRET` 单独配上。

> ⚠️ 这个变量**不只是为了登录**。会话 Cookie 的签名也靠它，而登录中间件验不过就一律返回 401 ——
> 也就是说**它没配（或填错格式），就算令牌配好了，保存也一样全部失败**。

### 2. `GITHUB_TOKEN` —— 用来读写仓库与 Gist

后台要访问两类东西，**权限必须都给**：

| 要访问的东西 | 需要的权限 |
|---|---|
| 博客仓库的文件（文章、图片、头像） | 仓库权限 **Contents：Read and write** |
| Gist（说说、笔记） | **Gists：Read and write**（在「账户权限」那一栏，和上面那项是分开的） |

- **细粒度令牌**：仓库权限勾 `Contents`，**另外**在账户权限里勾 `Gists` —— 只勾前者是最常见的错。
- **经典令牌**：勾 `repo` 与 `gist` 即可（要它顺手能推工作流文件就再加 `workflow`）。

配成「只有仓库权限」会怎样：文章、图片、头像都正常，**但说说和笔记保存不了**，
而且提示会绕一圈才看明白。这一点已在代码里兜住了：现在会直接说
「读不到这个 Gist（多半是令牌没有 Gist 权限，或 Gist 编号不对）」。

### 3. `AUTH_SECRET` —— 会话签名密钥

一串**长随机字符串**就行：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

不配也能跑（会回退用上面那个口令哈希当密钥），但建议单独配：以后想换登录口令时，
不会因为换了密钥把所有人的登录状态一起踢掉。

## 四、出问题时的对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 登录页写「服务端未配置登录密码」 | `ADMIN_PASSWORD_HASH` 是空的 | 见第 1 步 |
| 登录页写「ADMIN_PASSWORD_HASH 填得不对」 | 变量有值，但不是 64 位十六进制 —— 多半把**明文口令**填进去了 | 重新生成哈希再填（第 1 步）；这条是 2026-09-24 新加的，以前只会回一句「密码错误」，查不出原因 |
| 进得去后台，列表却「加载失败：令牌权限不足」 | 令牌没有仓库 Contents 权限 | 补仓库权限（第 2 步第 5 点） |
| 文章能存，说说/笔记报「读不到这个 Gist」 | 令牌缺 Gists 权限 | 补 Gists 权限（第 2 步第 6 点） |
| 保存报「内容在别处被改过，刷新页面重新打开再保存」 | 同一文件在别处也改过，本地拿的是旧版本 | 刷新页面重新打开再保存（这是**保护**，不是故障：避免把别处刚推的内容覆盖掉） |
| 保存报「请求太频繁，被 GitHub 限流了」 | 短时间写太多次 | 等一下再试 |
| 首页贡献日历只显示提交列表、没有热力图 | 令牌的 GraphQL 权限不足 | 不用管，这是**有意的降级**，不是坏了 |
| 填完变量还是老样子 | 忘了点 **Deploy** | 回第 3 步最后一步补上 |

## 五、为什么这一步在本地做不了

改这三个变量要动 Cloudflare 控制台。本机没有 Cloudflare 凭据
（没有 `wrangler` 的登录状态，也没有 API Token），所以只能人工去控制台填。
本地代码改动推上去之后，Cloudflare 会自己重新构建，不需要在本地做别的。

> 顺带提醒：仓库是主题作者仓库的 fork，往 `main` 推送走的是 GitHub API 那条路，
> 这种推法**不会自动触发仓库里的工作流**。想跑一次构建检查，得手动派发
> （`build.yml` 与 `biome.yml` 都带手动触发入口了）。

## 六、代码这边为这条链路做了哪些兜底

配置之外，保证「写得进去、写错了看得懂」的几件事（都在代码里，不需要操作）：

- **覆盖保护**：更新文件一定带上仓库里当前版本的 `sha`；本地版本过旧时 GitHub 会用 409 挡下来，不会静默覆盖。
- **变量填错与口令输错分开说**：`ADMIN_PASSWORD_HASH` 有值但不是 64 位十六进制时，登录接口回 503 并说明「这里要填哈希，不是口令本身」；口令确实不对才回 401「密码错误」。
- **没配权限时的报错指向明确**：不再只说「HTTP 403」或「网络错误」，而是把 GitHub 的原话带出来并翻译成一句人话。
- **Gist 读不到 ≠ Gist 里还没写内容**：前者报错并说明多半是权限问题，后者当作「还没写过」正常处理。
- **删除文章会连带清理它的图片目录**，改标题会把图片目录一起迁移。
- **图片上传前在浏览器里压缩**（最长边 1600、webp），避免把几 MB 的原图塞进仓库。
- **写了一半的内容先存本地**，关掉页面再回来能恢复；存进仓库后本地那份自动清掉。
