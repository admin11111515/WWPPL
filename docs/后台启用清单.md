# 后台启用清单

后台的「保存」是一条完整的链路：**在页面上点保存 → 服务端代理带着令牌写进 GitHub 仓库 → Cloudflare 自动重建 → 一两分钟后线上生效**。
代码这边已经齐了，但线上还差两个变量没填，所以目前**一次保存都没成功过**。

这份清单就是把它填完要做的全部事情，以及填完之后怎么确认真的通了。

---

## 一、先看链路长什么样

| 后台页面的动作 | 实际写到哪里 | 怎么生效 |
|---|---|---|
| 写文章 / 改文章 / 删文章 | 仓库 `src/content/posts/**` | 触发 Cloudflare 重建，1~3 分钟上线 |
| 上传文内图片、封面 | 仓库 `public/images/posts/<文章>/` | 同上 |
| 换头像 | 仓库 `public/assets/avatar.png` | 同上 |
| 写说说 | 一个 GitHub Gist 里的 `moments.json` | 页面刷新即见，**不用等重建** |
| 写笔记 | 一个 GitHub Gist 里的 `notebooks-entries.json` | 同上 |

两条路都**必须经过服务端的 `/api/github` 代理**：令牌只放在服务端，浏览器拿不到它。
所以浏览器里不管做什么，都要先过登录这一关 —— 这也是为什么下面的第 1 个变量不能省。

---

## 二、要配的三个变量

位置：**控制台 → Workers & Pages → firefly → Settings → Variables and Secrets**

### 1. `ADMIN_PASSWORD_HASH` —— 后台登录口令的哈希

**它不是某个固定值，而是「你自己定的那个口令」算出来的 SHA-256**，一共 64 位、全是十六进制字符。口令由你定，值由它推出来。生成一次、记下口令就行了。

| 填什么 | 结果 |
|---|---|
| 口令的 SHA-256（64 位十六进制），如 `b5c3…`（小写，共 64 字符） | ✅ 正确 |
| 你的口令原文，如 `my-password-2026` | ❌ 登不进去，登录页会直接提示「填得不对」 |
| 少几位、多一个符号的哈希 | ❌ 同样提示「填得不对」 |

生成方式，任选一种：

```bash
# 最省事：本机自带的脚本（会顺手把结果自查一遍）
node _gen/hash-password.mjs "你设的口令"
```

```bash
# 不想用脚本，用 node 一行
node -e "console.log(require('crypto').createHash('sha256').update('你设的口令','utf8').digest('hex'))"
```

```powershell
# 只有 PowerShell
[BitConverter]::ToString([Security.Cryptography.SHA256]::Create().ComputeHash([Text.Encoding]::UTF8.GetBytes("你设的口令"))).Replace('-','').ToLower()
```

填的时候注意四点（都已写进 `verify/2026-09-24/保存链路核验.mjs`，共 9 项断言）：

- **口令不做裁剪**：`abc ` 与 `abc` 是两个不同的口令。生成时用了空格，登录时也要带空格。
- **大小写十六进制都认**：服务端会先归一成小写再比，填成大写不会被挡。
- **粘贴蹭上的空格／换行会被忽略**：值两侧的空白不影响。
- **换口令 = 换密钥**。它是会话 Cookie 的签名密钥来源，改它就等于让所有登录状态失效（重新登录即可）。想让换口令不影响登录状态，就把下面的 `AUTH_SECRET` 单独配上。

> ⚠️ 这个变量**不只是为了登录**。会话 Cookie 的签名也靠它，而登录中间件验不过就一律返回 401 ——
> 也就是说**这个变量没配（或填错格式），就算令牌配好了，保存也一样全部失败**。

### 2. `GITHUB_TOKEN` —— 用来读写仓库与 Gist

⚠️ **这一项最容易配错，而且错法很隐蔽：配成一个权限不够的令牌，页面看起来"能用一半"。**

后台要访问两类东西：

| 要访问的东西 | 需要的权限 |
|---|---|
| 博客仓库的文件（文章、图片、头像） | 仓库权限 **Contents：Read and write** |
| Gist（说说、笔记） | **Gists：Read and write** |

**两类必须都给。** 选令牌类型时：

- **细粒度令牌（Fine-grained）**：仓库权限里勾 `Contents: Read and write`，
  另外还要在**用户权限**里勾一项 `Gists: Read and write` —— 这两项是分开的，只勾前者是最常见的错。
- **经典令牌（Classic）**：勾 `repo` 与 `gist` 即可（要它顺手能推工作流文件的话再加 `workflow`）。
  经典令牌的权限范围更粗，但对个人自用的小站更省事。

配成「只有仓库权限」会怎样：**写文章、传图片、换头像都正常，但说说和笔记保存不了**，
而且提示会绕一圈才看明白（GitHub 对没有权限的 Gist 返回的是"找不到"，不是"没权限"）。
这一点已经在代码里兜住了：现在会直接说「读不到这个 Gist（多半是令牌没有 Gist 权限，或 Gist 编号不对）」。

### 3. `AUTH_SECRET` —— 会话签名密钥

一串**长随机字符串**就行，例如：

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

不配也能跑（会回退用上面那个口令哈希当密钥），但建议单独配：以后想换登录口令时，
不会因为换了密钥把所有人的登录状态一起踢掉。

## 三、配完之后怎么确认真的通了

一条命令，对着线上跑：

```bash
node verify/2026-09-23/线上巡检.mjs
```

看最后那节「后台就绪度」：

- 两个变量都显示 `已配置` → 可以进后台试保存了
- `ADMIN_PASSWORD_HASH 未配置` → 登录接口返回 503，`/api/github` 一律 401
- `GITHUB_TOKEN 未配置` → 保存时服务端返回 503，并写明缺的是哪个变量

想更细一点，直接在浏览器里试：

1. 打开 `/admin/`，输入口令。失败时页面会写清原因（`服务端未配置登录密码` / `密码错误`）。
2. 进后台后写一篇短文保存。成功会有「发布成功 ✓」，一两分钟后刷新前台能看到。
3. 再去「说说」页发一条。这条走 Gist，**刷新即见**，不需要等重建 —— 也能顺便验证 Gist 那项权限有没有给对。

## 四、出问题时的对照表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 登录页写「服务端未配置登录密码」 | `ADMIN_PASSWORD_HASH` 是空的 | 见上面第 1 项 |
| 登录页写「ADMIN_PASSWORD_HASH 填得不对」 | 变量有值，但不是 64 位十六进制 —— 多半把**明文口令**填进去了 | 重新生成哈希再填（第 1 项）；这条是 2026-09-24 新加的，以前只会回一句「密码错误」，查不出原因 |
| 进得去后台，列表却「加载失败：令牌权限不足」 | 令牌没有仓库 Contents 权限 | 补仓库权限 |
| 文章能存，说说/笔记报「读不到这个 Gist」 | 令牌缺 Gists 权限 | 补 Gists 权限（细粒度里是单独一项） |
| 保存报「内容在别处被改过，刷新页面重新打开再保存」 | 同一文件在别处也改过，本地拿的是旧版本 | 刷新页面重新打开再保存（这是**保护**，不是故障：避免把别处刚推的内容覆盖掉） |
| 保存报「请求太频繁，被 GitHub 限流了」 | 短时间写太多次 | 等一下再试 |
| 首页贡献日历只显示提交列表、没有热力图 | 令牌的 GraphQL 权限不足 | 不用管，这是**有意的降级**，不是坏了 |

## 五、为什么这一步在本地做不了

改这两个变量要动 Cloudflare 控制台。本机没有 Cloudflare 凭据
（没有 `wrangler` 的登录状态，也没有 API Token），所以只能人工去控制台填。
本地的代码改动推上去之后，Cloudflare 会自己重新构建，不需要在本地做别的。

> 顺带提醒：仓库是主题作者仓库的 fork，往 `main` 推送走的是 GitHub API 那条路，
> 这种推法**不会自动触发仓库里的工作流**。想跑一次构建检查，得手动派发
> （`build.yml` 与 `biome.yml` 都带手动触发入口了）。

## 六、代码这边为这条链路做了哪些兜底

配置之外，保证「写得进去、写错了看得懂」的几件事（都在代码里，不需要操作）：

- **覆盖保护**：更新文件一定带上仓库里当前版本的 `sha`；本地版本过旧时 GitHub 会用 409 挡下来，不会静默覆盖。
- **变量填错与口令输错分开说**：`ADMIN_PASSWORD_HASH` 有值但不是 64 位十六进制时，登录接口回 503 并说明「这里要填哈希，不是口令本身」；口令确实不对才回 401「密码错误」。
- **没配权限时的报错指向明确**：不再只说「HTTP 403」或「网络错误」，而是把 GitHub 的原话带出来并翻译成一句人话。
- **Gist 读不到 ≠ Gist 里还没写内容**：前者报错并说明多半是权限问题，后者当作"还没写过"正常处理。
- **删除文章会连带清理它的图片目录**，改标题会把图片目录一起迁移。
- **图片上传前在浏览器里压缩**（最长边 1600、webp），避免把几 MB 的原图塞进仓库。
- **写了一半的内容先存本地**，关掉页面再回来能恢复；存进仓库后本地那份自动清掉。
