# 后台设计系统（2026-10-06「终极美化」那一轮定下来的）

> 这份是**后台（/admin/*）自己的设计约定**。前台博客那套在 `src/styles/variables.styl`，
> 两者共用同一批底层令牌（oklch + hue 驱动），但后台在 `admin.css` 里另立了一层
> 「可读性优先」的覆盖 —— 因为后台是**干活**的界面（Operate），不是读文章的界面。
>
> 判据与量法：`_gen/_后台设计缺陷普查.mjs`（对照 impeccable 的 craft-floor 检查项）。
> 前后截图：`_gen/_out/后台-前/` 与 `_gen/_out/后台-后/`。

## 一、色彩：强调色有**两个角色**，别再混用

| 令牌 | 用途 | 值（浅色 / 暗色） | 白底对比度 |
|---|---|---|---|
| `--primary` | **填充**（底色、色块、进度条） | oklch(.70 .14 hue) / oklch(.75 .14 hue) | 2.7:1 —— **不能当文字** |
| `--accent-ink` | **文字 / 图标 / 边框** | oklch(.48 .12 hue) / oklch(.80 .11 hue) | ≈5.6:1 ✅ |
| `--accent-solid` | 实心按钮的底 | oklch(.48 .13 hue) / oklch(.78 .12 hue) | 配 `--on-accent` |
| `--on-accent` | 压在实心底的文字 | oklch(.99 .003 hue) / oklch(.21 .02 hue) | 与上成对，≥4.5:1 ✅ |

**最常犯的错**：拿 `--primary` 写 `color:` 或 `border-color:`。
浅色主题里它是 oklch(0.70)，白底只有 **2.7:1** —— 文字读不清、焦点圈也看不见。
全站已归位 19 处；新写样式一律用 `--accent-ink`。

## 二、墨色四档，各自有下限

| 令牌 | 用途 | 白底 / muted 底 | 暗色底 |
|---|---|---|---|
| `--text` | 正文 | ≈13:1 | ≈13:1 |
| `--text-2` | 次要 | ≈7.5:1 | ≈7.5:1 |
| `--text-3` | 说明 / hint / 占位符 | ≈5.2 / 4.6:1 ✅ | ≈4.8:1 ✅ |
| `--text-4` | **只给装饰**（分隔线、状态点） | ≈3.2:1 —— 别写文字 | — |

原来 `--text-3` 是 `rgb(0 0 0 / .5)` = **3.98:1**，低于 4.5:1，
而后台所有说明文字都是它。**占位符也算文字**，也已从 `--text-4` 提到 `--text-3`。

## 三、门槛（都实测过，别凭感觉放宽）

- 正文 / 占位符 **≥4.5:1**；大字（≥18.66px 粗体或 ≥24px）**≥3:1**
- 焦点指示器 **≥3:1**（WCAG 2.2 焦点外观）→ 所以 `:focus-visible` 用 `--accent-ink`
- 触控目标 **≥24px**
- 汉字一行 **30~45 字**（后台表单不是长文，不用卡这条；文章正文用 `.custom-md` 的 42em）

## 四、表单控件全部自绘

`checkbox / radio / select / file` 一律 `appearance: none` 自绘（对勾走 mask、
下拉箭头走 background-image），颜色取 token。

⚠️ **两条铁律**：
1. **每个自绘控件都要自己写 `:focus-visible`** —— 关掉 `appearance` 会连原生聚焦圈
   一起关掉，这是自绘控件最常见的倒退。
2. **输入框基类不能用 `background` 简写**。简写会把 `background-image` 重置成 `none`，
   而 select 的下拉箭头就是靠它画的；再加上 `.input-single` 这类类选择器的特异性
   高于 `select` 元素选择器，简写会稳稳压住箭头 → 表现为「下拉变成没有箭头的一片白」。
   一律写 `background-color`。

## 五、间距 / 圆角 / 高程刻度

- 间距 `--sp-1..--sp-10`（4px 基准）；圆角 `--r-sm/md/lg/xl/full`
- 高程 `--ele-1/2/3`：**带偏移 + 柔光**，不用零偏移的彩色光晕
  （craft-floor 把「零偏移彩色光晕」列为装饰而非深度）
- 控件高度 `--ctl-h`(2.25rem) / `--ctl-h-sm`(2rem)
- 新样式**取值不写字面量**；同级元素在同一父级下的内边距应当一致

## 六、浏览器自带的表面（最容易被跳过的一档）

`caret-color` / `accent-color` / `::selection` / 滚动条 全部接到 token
（写在 `admin.css` 的「4c. 浏览器自带的表面」一节，锚在 `#admin-main` 上）。
数字/日期输入加 `font-variant-numeric: tabular-nums`。

## 七、侧栏是「第二层表面」

Operate 类界面的通行做法：侧栏 / 工具条 / 面板比内容面**差一档**，
用 `color-mix(in oklab, var(--card-bg) 62%, var(--page-bg))`。
原来侧栏和页面同色，整页看着是一块平的。

## 八、量法（改完必须跑）

```
node _gen/_后台设计缺陷普查.mjs      # 设计质量：原生控件 / 对比度 / 断行 / 间距 / 焦点 / 空白带
node _gen/_后台全页截图.mjs 前|后     # 9 页 × 桌面手机 × 明暗
```
功能侧另有十个回归脚本（易用性体检 / 控件体检 / 导航与路由 / 各功能核验），
**改样式也要跑** —— 自绘控件、色值改动都可能碰坏点击与判据。

⚠️ 写这类检测脚本的三个坑（都踩过）：
- 空白带**不能按某一栏算**（两栏不等高会误报 405px），要按"整屏横向贯通"算
- 「这一横带有内容」的门槛不能是"铺满 55% 宽度"（一行中文标题本来就很窄）
- `:focus-visible` **直接 `el.focus()` 测不出来**（只在键盘操作时命中），要真按 Tab
