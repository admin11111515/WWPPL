现象：有段代码调用外部接口，稳定地慢。每次差不多三秒，不快不慢，特别规律。

## 第一步：确认是不是接口慢

我先写了个最小复现，直接调那个接口，计时。

结果是平均 200 毫秒。

所以问题不在接口本身，在我调用它的方式上。

## 第二步：逐层加计时

我在调用代码的每一步之间插了计时打印：

```js
const t0 = Date.now();
const client = createClient();
const t1 = Date.now();
const res = await client.request(payload);
const t2 = Date.now();
console.log("创建客户端", t1 - t0, "请求", t2 - t1);
```

输出：创建客户端 2900 多毫秒，请求 200 毫秒。

找到了。

## 第三步：为什么创建客户端要三秒

读了一下这个客户端库的初始化逻辑。它在创建的时候会做一次网络请求——探测可用的服务节点，按延迟排序，选最快的一个。这个探测有超时设置，默认比较长。

而我的代码把它放在了循环里面。每处理一条数据就创建一个新客户端，每一条都付三秒的探测成本。

## 修法

把客户端提到循环外面，创建一次复用。改成之后整批处理从几分钟降到十几秒。

## 反思

这件事值得记下来的原因不是这个库，而是那三秒。

**三秒是个很典型的数字。** 网络请求的默认超时、连接池的空闲回收、DNS 的缓存失效——这些都是按秒计的。当你看到一个特别规律、特别整的数字（3 秒、5 秒、30 秒），第一反应应该是"这是某个超时配置"，而不是"网络卡了"。

另一个教训：**资源创建放循环里**。这是个老错误，我知道，但还是犯了。原因是那段代码是"先能跑通"写出来的，跑通的版本就是朴素地把所有步骤都写在循环里。

所以真正有用的做法不是"记住别这么写"，是在写完能跑的版本之后，主动过一遍：这里面有什么是每条数据都一样的？一样的部分就能拿出来。
