有段代码调外部接口，慢得特别规律，每次差不多三秒，不快不慢。

我同事阿松看了一眼说："你这延迟也太整了，跟设了闹钟似的。" 他这句话歪打正着，后来我才懂。

我先写了个最小复现，单独调那个接口计时，平均 200 毫秒。所以锅不在接口，在我调它的方式。

接着我在调用每一步之间插了计时：

```js
const t0 = Date.now();
const client = createClient();
const t1 = Date.now();
const res = await client.request(payload);
const t2 = Date.now();
console.log("创建客户端", t1 - t0, "请求", t2 - t1);
```

打印出来：创建客户端 2900 多毫秒，请求 200 毫秒。找到了。

我去看那个客户端库的初始化逻辑，它在创建时会发一次网络请求，探测可用节点、按延迟排序挑最快的。这个探测有默认超时，设得偏长。而我那段代码把它写在了循环里，每处理一条数据就新建一个客户端，每条都白付三秒探测成本。

改成创建一次、循环外复用，整批从几分钟掉到十几秒。

事后我想明白阿松那句话了：看到一个特别整的数字，三秒、五秒、三十秒，第一反应该是"这是某个超时配置"，而不是"网络卡了"。这类按秒计的东西太多了，连接池空闲回收、DNS 缓存失效，全是。

至于把建客户端写进循环，这是个老错误，我明明知道还会犯。那段代码是"先跑通"那版留下的，朴素地把所有步骤堆在循环里。所以现在写完能跑的版本，我会主动过一遍：这里面哪些东西每条数据都一样？一样的就拎出来。这个习惯比"记住别这么写"管用。
