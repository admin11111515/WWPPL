我博客是用 Astro 搭的，但这事我一开始没真搞懂。直到有回我自己测首页加载，DevTools 里 Network 一拉，下行的 JS 有 700 多 KB，我心里嘀咕"这破博客哪来这么多脚本"。

拆开看就明白了。文章正文是纯文字，根本不需要 JavaScript；点赞按钮要能点，评论区要能加载，这两块才需要。但原来整页都被一股脑打进脚本，正文也被拉进了"脚本世界"。

Astro 的搞法是：构建时就生成 HTML，正文直接是 HTML，打开就能看。点赞和评论是两块"岛"，只有它们加载 JS，而且能分别指定策略——点赞要马上能点，就"立即加载"；评论区在最底下，滚到附近再加载。

我把大部分组件都标成了"不需要 JS"。改完再测，脚本从 700 多 KB 掉到 90 多 KB，少了大概八成。首屏 HTML 一到就能读，不用等那一大坨。

怎么判断一块是不是"岛"？就一个问题：它会因为用户操作而变化吗？会变，就是岛，要 JS；不变，就是 HTML，别给它加脚本。我把自己站过一遍，侧边栏卡片、页脚链接、文章列表标题——这些以前都在脚本里，其实一点都不需要交互，纯属浪费。

也不是所有站都适合。我顺手给一个朋友弄后台，他看我用 Astro 搭，说"你这后台用 Astro 干嘛，直接上 Vue 不香吗"，说得对，我换成 Vue 了。Islands 最适合的是我这种"以内容为主、只有零星交互"的站：博客、文档、产品页。

改的过程里踩过一个坑：有回我把一个岛标成了"立即加载"，结果它依赖的数据在构建时还没好，线上打开直接报错 `Cannot read properties of undefined`。查了才知道是加载顺序的问题——这种细节文档里提得少，得自己踩。
