给站内图片加懒加载，当时想的是"这是标准做法，加上就行"。加完有两个地方出了问题。

首页顶部那张大图，是打开就看到的。它被懒加载之后，效果变成：文字先渲染，大图位置空着，过一下才补上来。浏览器要等布局完成、判断它是否在可视区才发请求。这个判断本身没多少耗时，但和 HTML 解析、样式计算挤在一起，就晚了几十到几百毫秒。这类图不该懒加载，它是首屏的一部分，越早下载越好。所以我给首屏图去掉懒加载，加上 `fetchpriority="high"`，让浏览器优先下它。

说实话这两类图我之前压根没想过会出问题。更烦人的是没写尺寸的图。懒加载的图没加载时占位高度是 0 或很小，等真实尺寸定了，它会把下面的内容全推下去。你正读着一段，图加载完，文字突然往下跳，眼睛跟丢位置。修法是给每张图写死宽高：

```html
<img src="..." width="800" height="450" loading="lazy" alt="..." />
```

有了宽高比，浏览器提前算好占位，加载完也不跳。响应式布局里 CSS 写 `width: 100%; height: auto;` 就行，比例由 HTML 的宽高属性维持。

现在首屏图都加 `fetchpriority="high"`，其他图懒加载，每张写死宽高。就这三句话，但我是被跳了两次才记住的。
