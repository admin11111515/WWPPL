博客的构建原来是这样：先跑图标生成，再跑图片占位图生成，然后构建，然后处理代码块的高亮，最后跑字体子集化和搜索索引。五条命令，顺序不能错。

少跑一条会怎样？最阴险的是少跑最后两条——网站能正常打开，看起来没问题，但字体没压缩，搜索没索引。你要点开搜索框试一下，才发现搜不到东西。

## 合并成一条

我把这五步串成一个脚本：

```js
const steps = [
  ["生成图标", "node scripts/generate-icons.js"],
  ["生成占位图", "npx tsx scripts/generate-lqips.ts"],
  ["构建站点", "astro build"],
  ["处理代码高亮", "npx tsx scripts/localize-code-blocks.ts"],
  ["字体子集化", "npx tsx scripts/subset-fonts.ts"],
  ["生成搜索索引", "node scripts/build-search-index.mjs"],
];
```

每一步执行完检查退出码，非零就停下，打印是哪一步炸的。

## 踩的坑

**npx 会停下来问你要不要装。** 这个在本地跑没事，因为包已经在了；换一台新机器或者 CI 上，npx 发现没装这个包，会弹出确认提示然后卡在那，等一个永远不会有的回答。加 `--yes` 就好。

**子步骤的日志会糊住。** 六个步骤的输出全部堆在一起，出错的时候很难看出是哪个阶段。解法是每一步开始前打印一行分隔，或者干脆把输出都收起来，失败时再打。

**构建产物要判断新旧。** 有一次构建失败了，但产物目录还是上一次的，我打开一看是好的，以为成功。后来加了一条：构建失败时明确打印"产物未更新，当前产物是旧的"。

## 顺手做的一件事

加了个 `--fast` 参数：只跑核心的构建，跳过耗时的字体子集化和索引生成。调样式的时候用它，一两秒出结果。

但这里有个陷阱要写清楚：**用 --fast 出的产物是半成品，不能用它判断体积和完整性**。我一开始没写这句话，后来自己就上过当——拿快模式的产物去测体积，得到完全错误的结论。
