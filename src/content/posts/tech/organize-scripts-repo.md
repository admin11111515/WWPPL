我写的小脚本到处都是：项目目录里、桌面上、甚至临时文件夹。这次花了一晚上收。

收之前同一个功能我写过 3 遍，因为忘了之前写过；想用一个脚本找不到，又重写；有些脚本依赖某个写死路径，换台机器就跑不了。最麻烦的是"忘了它存在"——写完只用过一次，就沉到某个目录里再想不起来。

我新建一个目录，按用途分层：

``
scripts/
  files/     文件批量处理（改名、归档、去重）
  images/    图片处理（压缩、转格式、批量剪裁）
  data/      表格与文本处理
  system/    本机相关（备份、清理、检查）
``

每个脚本第一行写句注释说干啥的，再写个 README 列出全部清单。

3 条我给自己定的规矩：路径必须能传参，不允许写死绝对路径，实在没招至少用相对路径或在开头顶个常量让人改；批量操作一律加 `--dry`，只打印会做什么、不动真格，这条救过我；跑完要打印结果，处理几个、跳过几个、为啥跳过，而不是一句"处理完成"。

我妈看见我整理脚本，说："你房间怎么不整理。" 我说这不一样。其实确实不一样，至少脚本找得到了。

整理完最有价值的不是脚本，是 README 里那份清单。以前遇到需求第一反应是"写一个"，现在会先翻清单，有能直接改着用的就改改。2 个脚本我换机器后完全跑不起来，查了半天才发现是依赖一个没装的库，写清楚之后下次就不用查了。
