我写的小脚本很多，散在各个项目目录里、桌面上、甚至临时文件夹里。这次花了一晚上整理。

## 整理前的状态

同一个功能写了三遍，因为忘了之前写过；想用一个脚本但找不到，重新写；有些脚本依赖某个路径，换台机器就跑不了。

最麻烦的是"忘了它存在"。写下之后只用过一次，然后就沉到某个目录里再也想不起来。

## 整理成什么样

新建一个目录，按用途分层：

``
scripts/
  files/     文件批量处理（改名、归档、去重）
  images/    图片处理（压缩、转格式、批量剪裁）
  data/      表格与文本处理
  system/    本机相关（备份、清理、检查）
``

每个脚本第一行写一句注释说它是干什么的，一个 README 列出全部清单。

## 三条规则

**一、路径必须可以传入。** 不允许写死一个绝对路径。想不出参数的办法，就至少要用相对路径，或者在脚本开头顶一个常量让人改。

**二、必须支持"只看不动"。** 批量操作的脚本，加个 `--dry` 参数只打印它会做什么。这条规则救过我。

**三、跑完要打印结果。** "处理完成"这种话没有信息量。要打印处理了几个、跳过了几个、跳过的原因是什么。这样出问题时不用回去读代码。

## 一个没想到的收获

整理完发现，最有价值不是脚本本身，是那个 README 里的清单。

以前我遇到一个需求，第一反应是"写一个"；现在会先看清单，有直接改改就用。

这改变了一点做事的方式：从"每次重新造"变成"先找找有没有"。

## 顺手做的事

给每个脚本加了执行权限的说明，和一句依赖提示（需要装什么、需要什么版本的运行时）。

因为有两个脚本我换机器之后完全跑不起来，查了半天原来是依赖一个没装的库。写清楚之后，下次就不用查了。
