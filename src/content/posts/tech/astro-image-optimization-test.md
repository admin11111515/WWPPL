一直知道 Astro 的 Image 组件能自动优化图片，但没认真测过到底省多少。这回拿博客的封面图比了一下。

同一张图两种写法。一是直接 img 标签引原图，相机导出的 JPG，单张 2.4 MB 左右；二是换成 Image 组件，指定宽度和格式让它自己转。

| 方式 | 格式 | 单张体积 |
| --- | --- | --- |
| img 直引 | JPG | 2.4 MB |
| Image 组件 | AVIF | 96 KB |
| Image 组件 | WebP | 178 KB |

差二十多倍。原因不神秘：原图 4000 像素宽、相机直出，实际展示位最多 800 像素宽，多出来的像素全白费。AVIF 比 WebP 又小一半，不过编码慢，构建时能明显感觉到时间变长，图多了要有心理准备。

我同事阿琳有回看到我页面加载完跳动一下，问我"你这图是后加载的吧，位置都没留"。其实就是没写尺寸。width 和 height 不写，图片加载完页面会跳，这就是排版偏移；写了浏览器能提前留位。所以现在我都老老实实标尺寸。

首屏那张图我吃过亏，一度也加了懒加载，结果第一屏慢一拍才出来。懒加载是给下面那些图用的，首屏第一张别懒。

还有原图别一起打包。转换后的图进产物目录，原图如果还搁在会被处理的位置，等于两份都发出去。我是把原图单独放，只让转后的进构建。

改完这遍写法，首屏那几张图加起来少了几 MB。花半小时，比抠 JavaScript 划算，这点我认。
