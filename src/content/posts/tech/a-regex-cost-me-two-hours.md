需求很简单：从一段文本里把姓名挑出来。姓名都是中文，两到四个字。

我一开始写的是这个：

```js
const re = /[\u4e00-\u9fa5]{2,4}/g;
```

看着没问题，实际跑出来发现：输入"张三丰（男）"，匹配到的是"张三丰"和"男"。括号没进去，但"男"进去了。

因为 `[\u4e00-\u9fa5]` 就是汉字区间，括号是标点不在里面，所以它会跳过标点继续匹配后面的字。

## 为什么不能简单加个边界

我第一反应是加个词边界 `\b`，但中文没有"词"这个概念，\b 在中文里不生效。

## 改成什么

最后我用的是先切分、再判断的思路，不再指望一条正则搞定：

```js
function pickNames(text) {
  // 括号里的内容直接丢掉
  const cleaned = text.replace(/[（(][^）)]*[）)]/g, " ");
  // 按非汉字段切开
  return cleaned
    .split(/[^\u4e00-\u9fa5]+/)
    .filter((s) => s.length >= 2 && s.length <= 4);
}
```

先去掉括号内容，再按"非汉字"把整段切开，剩下的每一段都是连续汉字，长度合适的就当候选。

## 教训

正则擅长匹配"形状固定的东西"，不擅长做"语义判断"。像"这两个字是不是人名"这种事，靠正则永远做不准——"而且""因为"都是两个字的中文。

我现在给自己定的线是：正则只负责切分和筛选格式，涉及判断的交出去。搞清楚这条线之后，很多纠结就没有了。

两小时，值。
