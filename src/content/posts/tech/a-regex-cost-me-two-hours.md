我那天要从一段文本里把姓名挑出来。姓名都是中文，两到四个字，需求就这么点大。

我一开始写的是这个：

```js
const re = /[\u4e00-\u9fa5]{2,4}/g;
```

看着没问题，跑出来才发现不对。输入「张三丰（男）」，它匹配到的是「张三丰」和「男」。括号没进去，「男」进去了。

我同事老陈端着杯子路过，瞥了一眼说："你这正则还想加词边界？中文哪有词这个概念。"

他一说我才反应过来：`[\u4e00-\u9fa5]` 是汉字区间，括号是标点，不在区间里，所以正则会跳过标点接着匹配后面的字。「男」本来就是个汉字，自然被抓进去。我第一反应想加 `\b`，其实 `\b` 在中文里压根不生效。

那两小时我基本是循环着 坂本龍一《async》 耗过去的，越听越烦。后来越想越觉得跟一条正则死磕没意思，改成先切分再判断：

```js
function pickNames(text) {
  // 括号里的内容直接丢掉
  const cleaned = text.replace(/[（(][^）)]*[）)]/g, " ");
  // 按非汉字段切开
  return cleaned
    .split(/[^\u4e00-\u9fa5]+/)
    .filter((s) => s.length >= 2 && s.length <= 4);
}
```

先丢括号内容，再按"非汉字"把整段切开，剩下的每段都是连续汉字，长度合适的就当候选。

说实话，正则干形状固定的活还行，干语义判断就是瞎子摸象。"而且""因为"都是两个字的中文，你指望它分出哪个是人名？分不出来。我现在给自己定的线是：正则只管切分和筛选格式，要理解意思的活交出去。

那两小时我记得清楚，一是卡得久，二是老陈那句话。后来翻规范才确认，`\b` 对 CJK 字符根本没定义，问题不在我想错，是它规范上就没这能力。
